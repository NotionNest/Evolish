# Easydict 功能对齐基线

> 用途：定义 Evolish 阶段一“完成 Easydict 功能对齐”的可验证边界。  
> 基线日期：2026-08-11  
> 依据：[Easydict 中文 README](https://github.com/tisfeng/Easydict/blob/dev/README_ZH.md) 与 [完整使用指南](https://github.com/tisfeng/Easydict/blob/dev/docs/zh/GUIDE.md)。  
> 原则：对齐用户能力和结果，不要求复制 Easydict 的界面像素或内部实现。

## 状态定义

- **待设计**：行为已明确，交互/技术方案尚未确定。
- **待实现**：设计和验收条件完整，可以进入工程开发。
- **通过**：自动化测试与人工平台验收均完成。
- **平台专属**：仅在拥有对应系统能力的平台适用，不计为其他平台缺失。
- **产品排除**：Evolish 通过已接受的产品决策明确不实现，不计为功能缺失，但必须验证产品中不存在对应配置或隐式请求。

当前所有适用实现条目初始状态均为“待设计”；明确标注的传统翻译服务和侧悬浮窗口初始状态为“产品排除”。

## A. 应用外壳与窗口

| ID | 能力 | 对齐行为 | 跨平台验收条件 |
|---|---|---|---|
| APP-01 | 常驻运行 | 关闭查询窗口后应用仍可从托盘和快捷键调用 | 三个平台窗口关闭后全局入口仍有效，退出动作才结束进程 |
| APP-02 | 托盘/菜单栏 | 提供输入翻译、划词、截图翻译、设置和退出入口 | 使用各平台原生托盘/状态栏能力；动作与快捷键行为一致 |
| APP-03 | 迷你窗口 | 自动划词、快捷键划词和截图翻译共用一个上下文结果窗口 | 不抢夺原应用输入焦点；跟随选区/截图上下文定位；屏幕边缘避让；支持转到主窗口 |
| APP-04 | 侧悬浮窗口 | 产品排除 | 不创建该窗口角色、WebView、配置或权限；对应结果能力由迷你窗口承担 |
| APP-05 | 主窗口 | 支持输入、持续查询和完整结果浏览 | 可选择启动时显示；窗口尺寸与位置持久化 |
| APP-06 | 双窗口独立查询配置 | 主窗口和迷你窗口可使用不同主服务、服务顺序与查询行为 | 修改一个窗口 profile 不影响另一个；查询按对应窗口快照执行 |
| APP-07 | 焦点管理 | 唤起输入翻译时聚焦输入框，结果窗不错误抢焦点 | 在连续唤起、切换应用、关闭后焦点归属正确 |
| APP-08 | 多显示器 | 窗口、选区图标和截图遮罩识别当前显示器 | 不越界、不出现在错误屏幕，支持不同缩放比例 |

## B. 文本获取与查询入口

| ID | 能力 | 对齐行为 | 跨平台验收条件 |
|---|---|---|---|
| CAP-01 | 输入翻译 | 全局快捷键唤起输入框，Enter 查询，Shift+Enter 换行 | 任意前台应用下可唤起；输入法组合态不被误提交 |
| CAP-02 | 快捷键划词 | 选中文本后按全局快捷键并在迷你窗口查询 | 浏览器、PDF、Office、编辑器、聊天软件测试集通过；不创建侧悬浮窗口 |
| CAP-03 | 自动划词 | 选择文本后显示查询图标，触发后打开迷你窗口 | 功能可关闭；图标不遮挡选择手柄或关键内容 |
| CAP-04 | 双击取词 | 双击单词可触发自动划词检测 | 在支持文本选择的测试应用中稳定识别单词边界 |
| CAP-05 | 拖动取词 | 鼠标拖动选择文本可触发检测 | 鼠标释放后获取完整选区，不包含额外剪贴板内容 |
| CAP-06 | 三击段落 | 三击选择段落后可触发检测 | 保留段落文本，正确进入句子/长文本判定 |
| CAP-07 | Shift 多段选择 | Shift 扩展或多段选择后可查询 | 能读取系统暴露的完整选区；不支持的应用明确记录限制 |
| CAP-08 | 取词策略 | 优先使用平台辅助功能；必要时使用平台自动化/复制链路 | 不破坏用户原剪贴板；失败给出权限或兼容性诊断 |
| CAP-09 | 深度链接 | 外部应用可通过 `evolish://query?text=...` 发起查询 | Unicode、空格、换行和特殊字符正确解码；非法请求安全拒绝 |
| CAP-10 | 外部工具调用 | macOS 支持 PopClip，其他平台可调用标准入口 | 外部调用结果与内部输入查询一致 |

## K. 对齐判定规则

阶段一只能在以下条件全部成立时标记为完成：

1. A–J 中所有适用 ID 均为“通过”，标记为“产品排除”的服务通过无配置入口、无请求验证。
2. Apple Dictionary 在 macOS 通过；在其他平台标记为“平台专属”，不得用名称相同但来源不同的服务冒充。
3. macOS、Windows、Linux 分别完成真实应用兼容性测试，而不仅是组件单元测试。
4. 服务适配器使用用户自己的合法凭据或明确可用的公开方式完成验收。
5. 阶段二学习功能没有以半成品形式进入阶段一界面。
