# Evolish 阶段一产品需求文档

> 状态：Accepted
> 更新日期：2026-08-11
> 参考对象：Easydict `dev` 分支当前公开功能
> 配套清单：[Easydict 功能对齐基线](./easydict-feature-baseline.md)
> 输入翻译细则：[文本输入翻译 PRD](./text-input-translation-prd.md)

## 1. 执行摘要

Evolish 阶段一将构建一个跨平台桌面词典与 AI 翻译应用，为需要在阅读、写作和日常工作中频繁理解外语内容的个人用户，提供低打扰的跨应用取词、输入翻译、截图 OCR、AI 查询、本地词典和语音能力。阶段一以 Easydict 的完整用户可见能力为对齐基线，并以明确产品决策替代传统翻译服务和默认并行请求。阶段一保存历史并提供结果收藏；阶段二的 AI 知识卡和复习系统不在本阶段实现。

## 2. 问题陈述

### 目标用户

阶段一的首要用户是产品所有者本人：需要高频阅读外语材料、查询单词和句子，并希望在 macOS、Windows 或 Linux 上获得一致工作流的学习者与知识工作者。

### 当前问题

- Easydict 的 macOS 原生体验完整，但不能覆盖其他桌面平台。
- Pot 虽然跨平台，但部分交互、信息组织和个人工作流不符合用户偏好。
- 翻译应用通常只返回一次性结果，输入上下文、服务结果和用户动作没有形成可供未来学习系统使用的稳定数据资产。
- 高频查询对操作路径极其敏感；窗口唤起、取词失败、权限提示、结果延迟或界面打断都会显著降低使用意愿。

### 用户任务（JTBD）

当我在任何桌面应用中遇到不理解的内容时，我希望用最短操作获得可靠、可比较、可朗读的解释或翻译，并能继续原本的阅读或写作，而无需切换到浏览器或整理中间数据。

## 3. 产品原则

1. **低打扰入口**：查询入口必须适配当前任务，不强迫用户切换到主窗口。
2. **结果可比较且费用可控**：主 AI 服务优先请求并展示；其他服务只有在用户展开时才按需请求，状态和结果保持独立。
3. **平台行为一致**：跨平台保持相同的用户心智；系统权限和系统服务采用平台原生实现。
4. **数据边界稳定**：所有入口产生统一的查询会话、来源上下文和结果模型，为阶段二提供可靠基础。
5. **配置归用户所有**：服务、密钥、顺序、窗口和快捷键均由用户控制，敏感凭证进入系统安全存储。
6. **阶段一完整交付**：以功能对齐矩阵全部通过为完成条件，不以功能子集替代最终目标。

## 4. 阶段一范围

### 4.1 查询入口

- 全局快捷键唤起输入翻译。
- 自动鼠标划词：双击、拖动选择、三击段落、Shift 多段选择。
- 全局快捷键查询当前选中文本。
- 区域截图 OCR 后翻译。
- 静默截图 OCR，结果直接写入剪贴板。
- 系统托盘/菜单栏入口。
- 深度链接调用查询。
- 从主窗口手动输入、粘贴和再次查询。

### 4.2 查询与语言处理

- 自动识别源语言。
- 根据语言规则和用户偏好选择目标语言。
- 手动选择与交换源/目标语言。
- 区分单词、句子和长文本查询类型。
- 智能查询模式。
- 首次只查询主 AI 服务；其他已启用 AI 服务在用户展开时按需查询。
- 每个服务独立加载、成功、空结果、错误、重试和取消状态。
- 针对不同窗口类型配置不同服务集合与顺序。

### 4.3 结果呈现

- 迷你窗口：承载自动划词、快捷键划词和截图翻译；默认紧凑显示，可展开适用的完整结果操作，也可将当前会话转到主窗口。
- 主窗口：承载持续输入、完整查询、历史、收藏、服务管理、设置和后续学习界面。
- 产品不提供侧悬浮结果窗口；设置作为主窗口内的页面/面板呈现。
- 显示原文、语言方向、词典/翻译结果、发音入口和服务状态。
- 支持复制原文、复制首个结果、重新查询、清空、固定窗口和关闭窗口。
- 支持浏览器搜索和外部词典调用。

### 4.4 OCR

- 跨显示器区域截图。
- 调用平台本地 OCR。
- OCR 文本进入统一查询管线。
- 用户可指定识别语言并重新识别。
- 静默 OCR 完成后自动复制文本且不展示翻译窗口。
- 支持 Easydict 当前列出的 OCR 语言范围：简体中文、繁体中文、英语、日语、韩语、法语、西班牙语、葡萄牙语、德语、意大利语、俄语和乌克兰语；平台引擎能力允许时可增加语言，但不能削弱基线。

### 4.5 词典

- macOS 接入 Apple 系统词典。
- 支持导入和查询 MDict 等第三方本地词典。
- 本地词典支持启用、停用、排序和结果来源标识。
- Apple 系统词典属于 macOS 专属能力；其他平台保持本地词典核心能力，不伪装为 Apple 服务。

### 4.6 翻译和 AI 服务

阶段一以 AI provider 能力覆盖翻译与语言分析，不复制 Easydict 的传统翻译服务目录：

- 原生 AI 协议：OpenAI、Anthropic、Gemini。
- OpenAI-compatible 自定义服务支持自定义地址、模型、密钥和请求参数；DeepSeek、Ollama、Groq、智谱 AI、GitHub Models 等兼容服务可通过该入口配置。
- 翻译、释义、例句和语言分析只由 AI 服务生成；本地能力负责语言检测和文本处理。
- 不接入 Apple Translate、DeepL、Google Translate、有道翻译、腾讯翻译、Bing 翻译、百度翻译、小牛、彩云、阿里翻译、火山翻译或豆包传统翻译接口。
- 首次提交只调用用户指定的主 AI 服务；系统不自动回退到其他服务。
- 其他服务默认折叠，首次展开时才请求；AI 完整生成并通过结构校验后一次展示。
- 需要认证的服务提供完整图形化配置、连通性测试和明确错误说明。

不把第三方服务的共享密钥或非官方网页接口视为产品可靠性的基础。若支持此类接口，必须明确标识其来源、限制和状态。

### 4.7 TTS

- 平台系统 TTS。
- Bing、Google、有道和百度在线 TTS。
- 用户可设置默认 TTS、声音和语速（服务能力允许时）。
- 支持查询后自动播放单词发音。
- 支持对原文或结果手动朗读、停止和重新播放。
- 服务失败时展示明确状态，并允许用户选择其他已配置服务。

### 4.8 设置与集成

- 配置全局快捷键与应用内快捷键。
- 启用、停用、排序和配置查询服务。
- 分别配置迷你窗口和主窗口使用的主服务、其他服务顺序与查询行为。
- 配置目标语言偏好、查询行为、自动发音、OCR 和 TTS。
- 配置开机启动、托盘图标、主窗口启动行为和窗口置顶行为。
- 提供 `evolish://query?text=...` 深度链接。
- macOS 支持 PopClip 调用；Windows/Linux 提供等价的标准外部调用入口。
- API 密钥、Cookie 和 Token 使用系统安全凭据存储，不写入普通配置文件或日志。

### 4.9 快捷键行为基线

Evolish 应提供与 Easydict 对应的动作，并使用各平台习惯的默认修饰键：

- 查询、插入换行、打开设置、退出应用。
- 清空输入；清空输入和结果；聚焦输入框。
- 复制查询文本；复制首个翻译结果。
- 播放发音；重试查询；交换语言。
- 固定/取消固定窗口；关闭窗口。
- 使用浏览器搜索；调用外部词典。

所有全局快捷键和主要应用内快捷键均应可重新绑定，并检测系统或应用冲突。

### 4.10 历史、收藏与隐私

- 成功查询默认保存到本地 SQLite，包含结构化输入、语言方向、服务、模型、翻译模式和结果版本。
- 用户可以搜索、筛选、删除、清空历史并配置保留期限。
- 用户可以关闭自动历史；主动收藏仍保存该结果所需的最小记录。
- 临时隐私模式不持久化输入、结果、来源上下文或搜索记录，退出后不得补写。
- 收藏引用明确的成功结果版本，支持收藏、取消、搜索和筛选；自动历史清理不删除收藏。
- 收藏不自动创建知识卡或复习任务。

## 5. 核心用户流程

### 5.1 自动划词

1. 用户在任意应用选中文本。
2. Evolish 获取文本、文本位置和来源应用。
3. 选区附近显示低干扰查询图标。
4. 用户悬停或触发后显示迷你窗口。
5. 本地识别语言和查询类型，先请求主 AI 服务；用户展开其他服务时再按需请求。
6. 用户复制、朗读、固定窗口或关闭，随后继续原任务。

### 5.2 快捷键划词

1. 用户选中文本并按全局快捷键。
2. Evolish 使用当前平台支持的取词链路读取文本。
3. 迷你窗口在当前选区或指针上下文附近出现并展示查询状态。
4. 主 AI 服务完整返回后一次展示；其他服务按用户展开动作请求，失败服务可单独重试。
5. 用户可在迷你窗口完成复制、朗读、收藏等结果操作，或将会话转到主窗口继续查看。

### 5.3 截图翻译

1. 用户按全局截图快捷键。
2. 选择任意显示器上的矩形区域。
3. 本地 OCR 返回文字和语言判断。
4. 迷你窗口在截图上下文附近显示可编辑原文并请求主 AI 服务；其他服务按需展开查询。
5. 用户可修正 OCR 语言并重新识别。

### 5.4 输入翻译

1. 用户按全局输入快捷键。
2. 主查询窗口出现且输入框获得焦点。
3. 用户输入或粘贴内容，按 Enter 查询，Shift+Enter 换行。
4. 系统完整生成后一次展示主 AI 结果并自动保存历史。
5. 用户可修改语言方向或翻译模式后重新查询，也可展开其他 AI 服务、复制、朗读或收藏结果。

## 6. 数据与扩展边界

阶段一内部至少形成以下稳定领域对象：

- `QuerySession`：一次查询会话，包含入口、时间、平台、来源应用和用户动作。
- `SourceContent`：原始文本、OCR 文本、语言、选区/截图引用和规范化内容。
- `QueryIntent`：词典、单词、句子、长文本或用户明确指定的模式。
- `ServiceRequest`：服务、语言方向、配置快照和请求状态。
- `ServiceResult`：结构化词典结果、翻译文本、音标、例句、发音和错误信息。
- `ContextMetadata`：来源应用、窗口标题、内容位置等可获得且经用户许可的上下文。
- `FavoriteReference`：用户收藏的稳定查询、服务 attempt 和结果版本引用。

阶段二可以引用上述对象和收藏结果生成知识卡片。阶段一显示历史与收藏，但不显示知识卡、复习队列或学习计划入口。

## 7. 完成标准与质量指标

### 核心完成标准

- [ ] 功能对齐矩阵内所有适用条目达到“通过”。
- [ ] macOS、Windows、Linux 各自的平台适配矩阵完成并通过人工验收。
- [ ] 五种核心入口均能进入同一查询管线并得到一致结果模型。
- [ ] 主 AI 服务失败不会自动产生备用请求；用户按需查询的其他服务保持独立且窗口不失去响应。
- [ ] 所有敏感配置均通过系统安全凭据存储管理。
- [ ] 权限未授予、服务未配置、额度受限、网络失败和 OCR 无结果均有明确可执行的错误状态。

### 体验指标

- 从快捷键触发到窗口可见的本地交互延迟目标：P95 不高于 150ms。
- 用户选择文本后，查询图标出现的本地交互延迟目标：P95 不高于 200ms。
- 取消截图、关闭窗口和重试查询均不会遗留遮罩、焦点锁定或后台悬挂任务。
- 空闲状态不持续占用显著 CPU；具体资源阈值在技术架构确定后固化为自动化性能基线。

### 兼容性验收

- 每个平台建立覆盖浏览器、办公软件、PDF 阅读器、编辑器、聊天软件和系统原生应用的取词测试集。
- 对测试集中的每个应用记录自动划词、快捷键取词、复制保护影响和已知平台限制。
- “支持”必须意味着连续重复操作稳定，不以单次成功作为通过标准。

## 8. 阶段一不包含

- AI 知识卡生成。
- 将收藏自动转换为知识卡、复习队列、间隔重复算法和学习计划。
- 课程、测验、学习统计和成长体系。
- 围绕阶段二概念暴露未完成的入口或界面。
- 移动端产品形态，除非后续明确将 iOS/Android 纳入阶段一平台范围。

## 9. 依赖与风险

### 主要风险

1. **跨应用取词差异**：三个桌面系统的辅助功能、剪贴板和自动化权限模型不同。
2. **AI 服务稳定性**：模型、配额、结构化输出能力和兼容接口可能变化。
3. **Apple 能力不可移植**：Apple Dictionary 只能在 macOS 提供原服务。
4. **OCR 差异**：平台本地 OCR 的语言、精度和返回结构不同。
5. **全局快捷键冲突**：操作系统、输入法和其他常驻应用可能占用组合键。
6. **GPL-3.0 边界**：若复制或派生 Easydict/Pot 的 GPL 代码，分发时需遵守相应许可证和源码义务；独立实现仍需保留来源研究记录。
7. **阶段二返工风险**：如果阶段一只存扁平翻译文本，未来知识卡将丢失上下文和结构信息。

### 控制原则

- 平台能力通过明确的系统适配层实现，上层查询和结果模型保持一致。
- 服务接入使用可替换适配器与能力声明，不让某一服务的数据结构渗透到产品核心。
- 主服务失败不触发隐式回退；其他 AI 服务只响应用户明确的展开或重试动作。
- 每项平台权限都提供首次说明、系统授权入口和授权状态诊断。
- 查询会话保留结构化上下文，但默认遵循最小采集原则。

## 10. 已关闭的产品决策

| 议题 | 决策 |
|---|---|
| 阶段一平台 | macOS、Windows、Linux 桌面端；移动端不在阶段一范围 |
| 交付顺序 | macOS → Windows → Linux；每个平台完成对应验收后再推进下一平台 |
| Linux 对齐 | X11 完整对齐；Wayland 按桌面环境和协议建立能力矩阵，不使用不可兑现的统一承诺 |
| 分发方式 | 公共仓库和公开二进制分发；正式发布前完成签名、可信更新与回滚验证 |
| 功能对齐方法 | 每项功能编码前先记录 Pot/Easydict 的具体不适点、期望结果和验收证据；对齐能力与结果，不复制其交互缺陷 |
| 翻译服务边界 | 翻译与语言分析仅使用 AI；传统翻译 provider 不纳入产品；本地词典作为独立能力保留 |
| 请求与展示 | 首次只请求主 AI，其他服务展开时按需请求；完整生成后一次展示 |
| 历史与收藏 | 阶段一自动保存本地历史并提供结果收藏；可关闭历史或使用隐私模式 |
| 阶段边界 | 阶段一完整交付 AI 翻译、词典、历史和收藏基础；知识卡与复习系统在阶段二独立设计 |
