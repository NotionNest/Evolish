# ADR-0002：平台交付策略

- 状态：Accepted
- 决策日期：2026-08-11
- 决策者：项目所有者

## 背景

阶段一要求 macOS、Windows、Linux 桌面端完整交付，但跨应用取词、窗口定位、OCR、TTS、权限和凭据能力都具有平台差异。Wayland 的协议边界尤其不允许把 X11 的全局坐标与窗口控制能力当作通用能力。

## 决策

平台交付顺序为 macOS → Windows → Linux。共享领域、应用和 UI 能力始终保持三端可编译；平台验收按该顺序完成。Linux X11 以完整功能对齐为目标，Wayland 以桌面环境、compositor 和 portal 为维度维护能力矩阵，只呈现实际可用能力。

所有平台能力通过 `PlatformCapabilityReport` 暴露。产品和 UI 依据能力而不是操作系统名称做决策。

## 结果

- 平台深度问题能在单一验收焦点下解决，同时共享代码持续接受三端构建验证。
- Wayland 用户得到准确的能力与恢复说明，而不是失败后才发现限制。
- 后续平台不得降低已经通过的共享查询、数据和错误契约。

## 被否决的方案

- 三个平台同时做完所有原生能力：并行反馈面过大，不适合当前维护规模。
- 仅支持 macOS：违背跨端目标。
- 宣称 Wayland 与 X11 无条件对齐：协议限制使该承诺不可验证。

## 验证要求

- CI 在 macOS、Windows、Ubuntu 构建完整 Tauri 应用。
- 每个平台具备真实应用取词、权限、窗口、OCR、TTS 和安装升级验收记录。
- Wayland 的每项功能必须标注支持、受限或不支持，并附桌面环境和协议依据。
